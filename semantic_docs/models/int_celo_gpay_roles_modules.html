int_celo_gpay_roles_modules

GP-specific Zodiac Roles module proxies on Celo, discovered natively from celo_execution.logs: an EnabledModule(<GP AggregateBridge>) event emitted BY a Roles proxy is a GP-only fingerprint set at card provisioning. Replaces the roles_with_bridge CTE of Dune query 7808895. Raw topic slicing, not the decode macro — this registry is itself an input to the decoded layer (see model header). Full rebuild every run; bounded by card count. The fingerprint matches ANY settlement contract seeded in celo_gpay_settlement_contracts (status active or migrating), not a single hardcoded address — both live bridges are GP's and are unioned. 1815 modules on 2026-08-05: 1580 on settlement_current 0xc07cd8c2…, 235 on settlement_legacy 0xc4df5cac…. See int_celo_gpay_safe_registry for the impact of the period when only the current contract counted.

Columns

NameTypeDescription
addressStringRoles module proxy address (0x-prefixed, lowercase).
contract_typeStringAlways 'RolesModProxy'.
first_seen_atDateTimeFirst EnabledModule(bridge) event for this proxy, i.e. card provisioning time. Migration does NOT reset it: a card that later wires a second bridge emits another EnabledModule from the same proxy, and the min() keeps the original.
wired_settlementsArray(String)Sorted distinct settlement contracts this Roles module has wired, and the migration tracker for GP's planned move off the legacy contract. One element is the normal state; TWO elements means that card has migrated and its payment history spans both bridges. Zero modules had two on 2026-08-05, i.e. migration had not started. Read migration state from here — never from a per-card generation column, which cannot represent a card that moved.
