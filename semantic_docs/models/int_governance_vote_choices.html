int_governance_vote_choices

One row per (proposal, voter, selected choice): Snapshot's polymorphic raw `choice` resolved to a label and a For/Against/Abstain direction. The foundation for every direction and contestation metric -- nothing downstream should parse choice_raw again. basic/single-choice yield one row per voter; ranked-choice yields one row per preference with vp only on rank 1. Unsupported ballot types (approval/weighted/quadratic, none currently used) yield NO rows by design -- the accepted_values test on ballot_type below is the guard: it fires the moment gnosis.eth enables a type this model cannot decode, before voters can silently vanish from the direction metrics. The 1-based positional mapping into choices[] was verified on 2026-07-28 by reconstructing every proposal's scores[] from summed vp_effective and reconciling against Snapshot's own reported scores[] -- exact match across all basic/single-choice proposals. That was a one-off check rather than a standing test, since tests/ here is reserved for heavyweight financial reconciliations; re-run it by hand if the ballot handling ever changes.

Columns

NameTypeDescription
ballot_typeStringSnapshot voting system for the proposal. The accepted_values test is a real guardrail, not a formality: a type outside this set cannot be decoded, produces zero rows, and would silently remove those voters from every direction metric. If it fails, add explicit handling in int_governance_vote_choices -- do not widen the list.
choice_indexUInt321-based index into the proposal's choices[] as cast by the voter.
choice_index_validBoolFalse when the index falls outside choices[]. Such rows keep an empty label and polarity 'unknown' rather than being mapped to a neighbour.
choice_kindStringsingle (basic/single-choice, one row per voter) | ranked (ranked-choice, one row per preference) | unsupported (emits no rows).
choice_labelStringThe option text the voter selected. Empty when the index is invalid.
polarityStringDirection of the selected option, from the shared classify_choice_polarity macro -- the SAME vocabulary int_governance_proposals uses for outcome, so a per-voter direction can never contradict the proposal-level result. 'other' is a real selection ballot outcome, not a failure.
preference_rankUInt321 for single-choice; ranked ballots count up in preference order.
proposal_idString
voterStringLowercased voter address.
vp_effectiveFloat64Voting power attributable to THIS row. Equals vp for single-choice; for ranked ballots only rank 1 carries vp (Snapshot resolves ranked by instant-runoff, not by splitting weight), so summing never double-counts a ranked voter.
