int_hopr_vpn_clients

GnosisVPN client nodes -- one row per (network, node_address). A client is a node that emitted a KeyBinding but NEVER an AddressAnnouncement: it joined the network without advertising itself as reachable, so it cannot be routed through and sits at the edge of the mixnet. This is HOPR's own definition, taken from the SQL behind their published GnosisVPN dashboard and adopted deliberately so our user counts are comparable to theirs rather than a parallel invention. It is STRUCTURAL -- derived from chain events, so it needs no maintenance as clients appear, unlike the hopr_node_registry seed which names exits from a git config and goes stale silently. Cannot be folded into int_hopr_nodes: that model's spine is announcement / safe-registry / channel activity, so a node that only key-bound is absent from it entirely -- which is exactly this population. One operator can run many nodes, so a row is an upper bound on a person. Clients register no Safe, so there is no on-chain identity to collapse them. rotsee rows are retained and flagged; the marts exclude them.
