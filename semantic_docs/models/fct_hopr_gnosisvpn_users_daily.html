fct_hopr_gnosisvpn_users_daily

GnosisVPN client activity per network per day, on a dense date spine -- the DEMAND side. Publishes two user definitions side by side and they are not interchangeable. active_users_* mirrors HOPR's own published definition (a client is active if it redeemed a ticket OR first key-bound in the window) and is the one to quote against their figures. using_users_* counts redemptions only, i.e. whether the product was actually used. The difference between them is the deployed-but-never-used cohort. The 30d window is 31 days inclusive while the 7d window is 7 -- an asymmetry copied deliberately from HOPR's query so the numbers line up; see the model header for why it is reproduced rather than corrected. There is no bandwidth column, by design: tickets are probabilistic payments, not bytes. rotsee (testnet) is excluded.
