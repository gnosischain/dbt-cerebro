int_hopr_channels_events

Normalized HOPR payment-channel events across both live networks. Reconciles three differences between the deployments: (1) dufour emits typed scalars while jura emits the raw packed storage word (balance uint96 | ticketIndex uint48 | closureTime uint32 | epoch uint24 | status uint8, low bits first), unpacked here and verified against blokli's API to the exact wei; (2) dufour's ChannelOpened carries no channelId, so it is derived as keccak256(source || destination) -- verified against 52/52 real events; (3) source/destination appear only on ChannelOpened, so they are filled across each (network, channel_id) partition, which is sound because channel_id is a pure function of the endpoint pair and therefore invariant across channel reopens. Materialized as a table rather than an incremental append: the expensive log scan already happened upstream, so a full rebuild is cheap and avoids the append-watermark and append-over-populated-partition hazards.

Columns

NameTypeDescription
balance_weiNullable(UInt256)Channel balance AFTER the event, in wei. NULL where the event carries no balance observation (dufour ChannelOpened and ChannelClosed) -- must stay NULL so the delta window does not diff against a fabricated zero.
channel_idStringChannel identifier, keccak256(abi.encodePacked(source, destination)). Derived for dufour ChannelOpened, taken from the event elsewhere.
channel_statusStringDecoded ChannelStatus; 'unknown' on dufour, which does not emit it
event_nameString
is_testnetBoolTrue for rotsee, inherited from contracts_hopr_registry so the rule is defined once. Kept at this layer rather than filtered: the testnet stays analysable here and the fct_/api_ marts exclude it. Never sum a metric across this flag.
networkLowCardinality(String)dufour (legacy production), jura (v4 / GnosisVPN) or rotsee (v4 testnet). Each v4 network spans TWO contract deployments -- the pre-2026-07-27 generation and the current one -- so network is not one address.
packing_overflow_checkNullable(UInt256)Guard on the jura bit layout itself: the packed struct occupies bits 0..207, so anything at bit 208 or above must be zero. A non-zero value means the Channel struct changed and the unpacking offsets are stale.
redeemed_weiNullable(UInt256)Value paid out to the destination node on a ticket redemption, derived as the drop in balance on ChannelBalanceDecreased. Scoped to that event because a channel closing also drops the balance but returns funds to the source instead.
ticket_indexNullable(UInt64)Channel's ticket index after the event. NOT a ticket count -- it advances by a ticket's index RANGE, so jura channels reach millions within a week. Never aggregate as a volume.
