int_hopr_nodes

HOPR node dimension, one row per (network, node_address). Turns three previously dead-end decode streams into something usable: before it, only contracts_hopr_Channels_events had any consumer, while Announcements, NodeSafeRegistry and NodeStakeFactory were decoded but referenced by nothing. Joins node identity to its Safe (operator), its announced IP (geo/ASN/hosting via the same stg_crawlers_data__ipinfo view the p2p models use), its declared class, and its channel earnings as a relay destination. The operator dimension is the point: safe_address is what makes nodes-per-operator computable, the one HOPR decentralisation metric that is not a vanity count. Also carries per-node liveness from the network.hoprnet.org prober. That matters because on-chain presence is cumulative and never expires: without it this model cannot tell a node running today from one that registered in 2023 and vanished, and most of the rows here are the latter. liveness_source says which case each row is. dufour only -- the prober was never ported to jura.

'not_probed' IS NOT A SYNONYM FOR DEAD. The roster is not the population of record: a substantial minority of unprobed nodes still show on-chain channel activity, some within the last day. Absence correlates with dormancy and does not establish it, so use last_channel_activity_at to judge whether a node is alive and treat this column purely as "did the prober look at it".
