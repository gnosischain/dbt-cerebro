fct_celo_gpay_card_funnel

One row per card - issuance, first funding, first spend, and the lags between. The atom behind fct_celo_gpay_funnel_cohorts_monthly. Every column is measured as of ONE horizon, `observed_through`, taken from int_celo_gpay_activity_daily. The three signals come from models built at different times (int_celo_gpay_wallets rebuilds fully each run and reaches head; int_celo_gpay_activity_daily is incremental and lags), so without a shared horizon a card issued yesterday reads as issued-but-never-funded purely because funding has not been built yet. Cards issued after the horizon are excluded, and first_spend_at is clipped to it even where wallets already knows it. NEVER divide is_funded by row count to get a conversion rate. Issuance is still ramping, so most cards are young and "unfunded" mostly means "issued recently". Use observation_days to restrict to cards old enough to have had a fair chance, or read fct_celo_gpay_funnel_cohorts_monthly which does it for you. first_fund_channel is the funding_channel of the card's FIRST inbound transfer (from int_celo_gpay_funding_tx_envelopes). It is a shape classification, not an identity label — CIP-64 alone is not MiniPay. NULL when the card has never been funded. Channel values (same glossary as fct_celo_gpay_card_funding): cip64_direct_solo — CIP-64 (tx type 123) + funder EOA called token.transfer() + that funder funds exactly one card. MiniPay-shaped; do not rename to "minipay" without an off-chain identity source. other_direct — same direct EOA transfer() shape, but envelope is not CIP-64 (type 0/2), and the funder funds exactly one card. hub — this first-fund's funder funds two or more cards (fan-out wins over envelope; includes the legacy 0xa0dd… onboarding hub). mediated — first fund was not a direct EOA→token transfer (e.g. Safe execTransaction). mixed — reserved for relationship-level disagreement on fct_celo_gpay_card_funding; first_fund_channel reads per-transfer envelopes so it does not emit mixed today, but the value stays accepted. unknown — funding transfer row exists but no matching transactions row.

Columns

NameTypeDescription
days_fund_to_spendNullable(Int32)Days from first funding to first spend, for cards that did both. Legitimately 0 - funding and spending the same day is the common MiniPay pattern (152 cards).
days_issue_to_fundNullable(Int32)Days from issuance to first funding. NULL where the card has never been funded.
days_issue_to_spendNullable(Int32)Days from issuance to first spend. NULL where the card has never spent.
first_fund_channelNullable(String)funding_channel of the card's first inbound transfer. Shape classification, not MiniPay identity. NULL if never funded. See model description for values.
first_funded_atNullable(Date)Date the card first RECEIVED money - the first inbound action (Top-up, Reversal or Cashback) in int_celo_gpay_activity_daily. NULL if it never has, which is distinct from a zero lag.
first_spend_atNullable(Date)Date the card first SPENT - a stablecoin settlement to a bridge, from int_celo_gpay_wallets.first_spend_at, clipped to observed_through so it cannot run ahead of the funding signal.
is_activatedBoolCard has ever spent as of observed_through. Matches int_celo_gpay_wallets.is_activated except where a spend falls after the horizon.
is_fundedBoolCard has ever received money as of observed_through.
issued_atDateDate the Safe was provisioned as a card (SafeSetup), from int_celo_gpay_wallets.
observation_daysInt32Days from issuance to observed_through - how long this card has been observable. The eligibility gate for every conversion rate built on this table.
observed_throughDateThe as-of date for the whole row, from max(date) in int_celo_gpay_activity_daily. Identical on every row; carried per-row so a consumer reading a slice can still see the horizon.
safe_addressStringGP card Safe address. One row per card.
